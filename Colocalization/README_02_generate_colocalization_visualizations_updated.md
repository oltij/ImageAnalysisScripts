# `02_generate_colocalization_visualizations.py`

This README documents the current `02_generate_colocalization_visualizations.py` visualization/QC stage.

The script reads the HDF5 analysis file produced by `01_run_colocalization.py` and generates PDFs, CSVs, TIFFs, class summaries, organoid-area metrics, and unmatched-object QC outputs. It does **not** rerun the Object-A/Object-B colocalization matching itself.

This document is intentionally limited to this script.

# 8. `02_generate_colocalization_visualizations.py`

Source script:

```text
02_generate_colocalization_visualizations.py
```

---

## 8.1 Purpose

This is the visualization/QC-only stage.

It reads the single HDF5 analysis file generated by:

```text
01_run_colocalization.py
```

It does **not** recalculate the stable matching.

This allows display and QC settings to be changed freely without rerunning the colocalization analysis.

### Supplemental inputs for the true all-cell nuclear summary

With the current setting:

```python
ENABLE_NUCLEAR_ALL_CELL_SUMMARY = True
```

the script also reads the two original marker-vs-nuclear analysis HDF5 files:

```python
OBJECT_A_NUCLEAR_RESULTS_FILE = Path(
    "/home/oltij/Desktop/Aligned_DAPILHX6_colocalization_results_25_new/"
    "Aligned_DAPILHX6_colocalization_analysis.h5"
)

OBJECT_B_NUCLEAR_RESULTS_FILE = Path(
    "/home/oltij/Desktop/Aligned_DAPIPV_colocalization_results_25_new/"
    "Aligned_DAPIPV_colocalization_analysis.h5"
)
```

Conceptually:

```text
OBJECT_A_NUCLEAR_RESULTS_FILE = Object A ↔ Hoechst/DAPI first-stage analysis
OBJECT_B_NUCLEAR_RESULTS_FILE = Object B ↔ Hoechst/DAPI first-stage analysis
```

These files are used only to recover the **pre-existing marker-to-nucleus assignments**. The visualization script does not perform a new marker-to-nucleus spatial match.

If either path is `None`, the all-cell summary is skipped. If enabled and a path is supplied but the file is missing or incompatible, the script raises an error.

### Nuclear denominator compatibility

Current setting:

```python
ALLOW_NESTED_NUCLEAR_OBJECT_SETS = True
```

The two marker-vs-nuclear source runs are handled as follows:

```text
identical nuclear ObjectID sets
    -> use that shared nuclear set

one nuclear ObjectID set is a strict subset of the other
    -> use the union / larger set

partially different, non-nested nuclear ObjectID sets
    -> stop with an error
```

This prevents the script from silently combining incompatible nuclear segmentations or ID namespaces.

# 23. Organoid-area summary metrics

```text
Object_B_Positive_Area_Pixels
Object_B_Positive_Area_um2
Object_B_Positive_Area_Percent_of_Organoid
```

## 23.1 Organoid denominator

The denominator is the sum of positive finite values from the configured CellProfiler organoid area column:

```text
AreaShape_Area
```

If multiple organoid rows are present, their areas are summed.

Pixel area is converted to square micrometers using:

```text
PIXEL_SIZE_X_UM × PIXEL_SIZE_Y_UM
```

from the current analysis metadata.

## 23.2 Marker-positive numerator

For each marker, the numerator is the **union of all pixels occupied by that marker's current ROIs**.

This is important:

```text
marker-positive area is independent of the final A/B matching
```

Therefore the area numerator includes both final matched and unmatched positive marker ROIs.

A union mask is used so overlapping ROIs from the same marker cannot double-count the same pixel.

The reported percentages are:

```text
Object_A_Positive_Area_Percent_of_Organoid
    = union Object-A-positive pixels / organoid area pixels * 100

Object_B_Positive_Area_Percent_of_Organoid
    = union Object-B-positive pixels / organoid area pixels * 100
```

# 26. How the all-cell nuclear denominator is built

The source of truth is the nuclear `ObjectID`, not the run-local `CellID`.

The script compares the nuclear ObjectID sets stored in the two original marker↔nucleus HDF5 files.

## 26.1 Identical nuclear sets

If the sets are identical:

```text
Nuclear_Denominator_Method = identical_source_nuclear_sets
```

and that shared set is used.

## 26.2 Nested nuclear sets

If one set is a subset of the other and:

```python
ALLOW_NESTED_NUCLEAR_OBJECT_SETS = True
```

the union/larger set is used:

```text
Nuclear_Denominator_Method = nested_source_nuclear_sets_union
```

This supports the case where the same nuclear segmentation was filtered differently between the two first-stage runs while preserving a compatible ObjectID namespace.

## 26.3 Non-nested nuclear sets

If each source contains nuclear IDs that the other lacks, the script raises an error instead of creating an all-cell summary.

This is treated as evidence that the two HDF5s may represent different nuclear segmentations or incompatible ID namespaces.
